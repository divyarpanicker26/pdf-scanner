Design

One page in the browser does the whole job

1. Open the PDF

pdfText.ts uses PDF.js. If a page has almost no text, Tesseract.js reads the image.

2. Match the fields

extract.ts looks for each label or pattern and returns a value or “missing.”

3. Staff check

App.tsx shows the page preview and JSON. Copy or download. Nothing is uploaded.

Field lists live in fields.ts. Types live in types.ts. Sample PDFs are built by scripts/make-nycha-samples.mjs.

How the code is split
Each field on the screen

Four settings tell the tool what to pull out

SettingWhat it isExample
JSON keyThe name of the value in the result. Use this later if you send data to Siebel.caseNumber
Label in the documentThe printed words to find, usually at the start of a line, then a colon.Case Number
Regular expressionOptional. A search pattern. If this is filled in, it replaces the label rule. The first group in parentheses is the value.SR-(\d+) keeps only the digits
Continue on the next linesKeeps following lines until a blank line or another label. Used for addresses.Street, apartment, city on three lines
A field also has a hidden id so the list can be edited. Duplicate JSON keys are rejected. An invalid pattern is reported on that field.
Field settings
How a value is found

Label first. Pattern only if you set one.

If the pattern box is empty

The tool looks for a line that starts with the label, ignoring capital letters. The text after the colon is the value. If that line is empty, it takes the next line. If “continue on the next lines” is on, it joins extra lines with commas.

If a regular expression is set

The label is ignored. The pattern is matched against the whole PDF text. The first capture group becomes the JSON value. If there is no group, the whole match is used.

Example: the PDF says Case Number: NYC-0001842. JSON key caseNumber and label Case Number produce "caseNumber": "NYC-0001842".

Environments
Updating server details

Change configuration. Do not rewrite the extractor.

What you would set per environment

  • Website address — local, GitHub Pages, or NYCHA hosting.
  • API or Siebel URL — empty today; test URL in UAT; production URL only in prod.
  • Environment name — local, demo, test, or prod.
  • OCR files — download from the internet, or serve them from the same host.

How to update them

Vite reads values that start with VITE_ at build time. Example:

VITE_ENV=test
VITE_API_URL=https://siebel-test.nycha.example/api
VITE_OCR_LANG_PATH=/tessdata

Build once for each environment. The TypeScript in extract.ts and pdfText.ts stays the same. Only the URL and environment name change.

Configuration
If the PDF itself differs by environment

Point the field list at that environment’s form

  • If test and production use the same labels, keep one field list. Only the hosting and Siebel URL change.
  • If a test form uses different wording, for example “Account No.” instead of “Account Number,” change the label on that field. Leave the JSON key as accountNumber so Siebel still receives the same name.
  • If a whole packet exists only in one environment, add a field list in fields.ts (or load it from a JSON file) and choose it from the Demo PDF list.
  • Do not put passwords, Siebel credentials, or production URLs inside the PDF or in GitHub Pages.
The JSON key is the contract with Siebel. The label is what is printed on that environment’s PDF. Keep those two ideas separate.

Summary

What to remember

  • The code is TypeScript and React, with PDF.js and Tesseract.js, built by Vite into a static website.
  • Each field is a JSON key, a label, an optional pattern, and a multiline flag.
  • There is no application server today. PDFs stay in the browser.
  • To move from demo to NYCHA test or production, update hosting and API URLs in environment settings. Do not rewrite the matching code.
  • If a form’s wording changes, update the label. Keep the JSON key stable for Siebel.
